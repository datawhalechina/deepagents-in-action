Human-in-the-Loop 执行流程 — 中断、人工决策与恢复

目标：为中文技术课程生成一张清晰、可读、与本课程既有插图风格一致的 16:9 流程图，用于解释 Deep Agents / LangGraph 的 HITL 工具审批流程。

风格参考：会随生成命令传入 3 张现有课程图片作为 reference。必须学习它们的字体、线条和版式：
- 像白板/Notion 手绘课程图，而不是 Figma/Keynote 商务 UI 图
- 中文字体是圆润、轻松的手写 marker 风格，笔画粗细自然，不是黑体、思源黑体、苹方、粗体标题字
- 英文/API 关键词是干净的手写 monospace / marker 风格，不是系统 UI 字体
- 线条是轻微手绘感的深灰细线，箭头可有铅笔阴影或斜线填充
- 背景是轻微纸张纹理或很浅的灰白，不要纯白发光，不要玻璃拟态
- 卡片边框是薄的、略圆角、略手绘，不要厚重阴影和立体按钮

画面标题：
「Human-in-the-Loop：中断 → 人工决策 → 恢复」

整体布局：
- 16:9 横向课程图，浅色背景，适合网页文章阅读
- 主流程从左到右，共 5 个主要节点
- 第 4 个节点「人工审查」向下展开 4 个并列决策分支
- 所有文字必须是简体中文，API 关键词可以作为小号英文标签保留
- 不要使用复杂 3D、照片、拟物插画、过多装饰图标
- 不要使用粗重的现代 UI 字体，不要像 SaaS Dashboard 截图

主流程节点：
1. 「Agent 运行」
   - 小标签：规划任务
   - 图标：简洁齿轮或节点网络

2. 「调用敏感工具」
   - 小标签：delete_file / send_email
   - 图标：警告三角

3. 「中断暂停」
   - 小标签：返回 action_requests
   - 图标：暂停按钮
   - 使用淡黄色高亮，表达“暂停等待”

4. 「人工审查」
   - 小标签：查看参数与 review_configs
   - 图标：用户头像 + 勾选清单
   - 从这里分成 4 个决策分支

5. 「恢复执行」
   - 小标签：同一 thread_id + Command(resume)
   - 图标：播放按钮或继续箭头

四个决策分支（从「人工审查」向下展开，四张小卡片并列）：
- 绿色卡片：「批准」
  - 小号 API 标签：approve
  - 说明：按原参数执行工具

- 蓝色卡片：「修改」
  - 小号 API 标签：edit
  - 说明：修改参数后执行

- 红色卡片：「拒绝」
  - 小号 API 标签：reject
  - 说明：跳过工具并反馈原因

- 紫色卡片：「响应」
  - 小号 API 标签：respond
  - 说明：人工提供 ToolMessage

分支回流：
- 「批准」和「修改」汇入「执行工具」
- 「拒绝」和「响应」汇入「ToolMessage」
- 「执行工具」和「ToolMessage」再汇入「恢复执行」

视觉风格：
- 与参考图完全同一套「Notion 手绘白板课件」质感
- 字体：中文手写 marker 风格，标题可大但不要粗黑；正文更轻、更圆润
- 圆角卡片、细线箭头、轻微手绘抖动、少量斜线阴影
- 背景：#F8FAFC 或接近白色，带轻微纸张纹理
- 主节点：白色卡片 + 深灰手写字
- 中断节点：淡黄色 #FEF3C7
- approve：绿色 #16A34A
- edit：蓝色 #2563EB
- reject：红色 #DC2626
- respond：紫色 #7C3AED
- 文字颜色：深灰 #111827

文字约束：
- 中文必须清晰可读，不能乱码
- 不要把标题、标签写错
- 不要出现额外英文段落或解释性长文
- 不要遗漏 respond 分支
- 不要把 respond 画成“批准”
- 不要把中文渲染成粗黑系统字体；要接近参考图里的手写中文字体
- 不要让标题过粗或过紧；标题字距自然，像白板标题

输出要求：
- 画面干净、有留白
- 所有节点与箭头不重叠
- 网页文章中缩放到 800px 宽时仍然能看清主要文字
- 适合替换现有的 HITL 流程图
